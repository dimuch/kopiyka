# Architecture audit — October 2026

Scope: `apps/api` and `apps/mobile` at `origin/main` (`c60c564`), read-only. Yardstick:
`.claude/skills/kopiyka-conventions/SKILL.md` (§ numbers below refer to it), with the
`codebase-design` vocabulary and a `code-simplification` pass. Two subagents audited the API
and the app in parallel. Every Critical and Important finding was then re-checked against the
source in a skeptic pass; what didn't hold was dropped or downgraded (see the end of the
findings table). API typecheck and lint pass; DB tests were not run.

## Summary

1. **Healthy overall, no Critical findings.** Small (~4.4k lines), consistently structured, and
   the domain split in §2 is followed almost everywhere. Comments explain _why_.
2. **Money and ledger scoping are solid.** Bigint cents end to end on the API, decimal strings on
   the wire, `convert` half-up with tests that show the arithmetic. Every
   `/api/ledgers/:id/...` route has `[requireAuth, requireLedger]` and joins through
   `categories.ledger_id`; non-members get 404.
3. **The real risks are in login hardening.** The 5-strikes throttle can be exceeded with
   concurrent requests, and `trustProxy: true` lets a client choose the IP that gets throttled.
4. **The app's weak spot is `app/expense.tsx` (453 lines).** It loads data inline with no unmount
   guard, syncs derived state through an effect behind two lint suppressions, and computes
   "today/yesterday" in device-local time. No async screen offers a retry, and a failed Undo is
   swallowed.
5. **What's good:** real seams (`AppDeps.now/fetchRate/db`, `nbuFetcher(fetchImpl)`), so tests
   run against real MySQL with no module mocks and no network. Careful auth: hashed session
   tokens, AES-GCM TOTP secrets, atomic replay guard, IPv6 /64. A discriminated `AuthState` with
   `Stack.Protected`. Platform branching kept at the edges (`client.ts`, `DateField`,
   `confirmDelete`).

  (`expenses.int.test.ts:114-126,193-197`).

  fixed fragments or `?` lists chosen in code.

  untested _today_ because of it; it's cleanup that pays off once one exists.
- _M1 Kyiv dates_: kept Important because it breaks a stated §3 invariant, but the practical
  impact is small. The API accepts dates up to Kyiv tomorrow, and Kyiv is ahead of the EU.
- _A1 throttle race_: kept Important. It's reachable with `Promise.all`, but bounded by the
  10-connection pool and by needing a valid username; each extra guess has a ~3·10⁻⁶ chance.
- _A2 trustProxy_: kept Important. If nginx happens to overwrite the header with
  `$remote_addr`, today's deployment is safe, but only by accident.
- _"Session-expiry 401 crashes a protected screen via `useSession` throw"_
  (`AuthContext.tsx:72-75`): dropped as unconfirmed. Worth a manual check on iOS: let a session
  expire on the Category screen.

## Not a problem

Things that look wrong but are intentional or correct:

- **`addDays`/`isCalendarDate` use `Date`** (`apps/api/src/dates.ts:8,13`). These are the
  sanctioned UTC-midnight helpers §3 names; nothing else does calendar arithmetic on the API.
- **`rateToE4(number)` takes a float** (`apps/api/src/money.ts:22-24`). The NBU returns JSON
  numbers, `Math.round` removes representation error, and §3 names it.
- **`new Date()` in `apps/api/src/server.ts:8`.** That's the composition root building the `now`
  seam. No other `Date.now()`, direct `fetch` or imported pool in the API.
- **Username lockout lets a stranger lock a user out** (`throttle.ts:4-5`), and **the IP count is
  never reset** (`throttle.ts:94`). Both are documented trade-offs.
- **The unknown-username path still runs `generateSecret()` + `verifyTotp`**
  (`auth/routes.ts:55`). It equalises timing and the answer.
- **`updated_at = e.updated_at` in `setDeleted`** (`expenses/routes.ts:190`). Commented: a delete
  isn't an edit.
- **PUT skips the category check when the category is unchanged** (`expenses/routes.ts:162`).
  Staying in a since-hidden category is allowed and tested; the app mirrors it.
- **`expenses` has no `ledger_id` column.** Scoping goes through the `categories` join,
  consistently (except A5).
- **Unused tables `ledger_invites`, `category_budgets`** (`migrations/001_initial.sql`). They're
  from the planned data model, and migrations are forward-only.
- **`categories/routes.ts` reads the `expenses` table.** It's a read for its own DTO, with no import
  from the expenses domain. The only cross-domain import is `expenses → rates/service`, which is
  what §2 intends.
- **`req.auth!` / `req.ledger!`** are guaranteed by the preHandlers on every route that uses them.
- **`scripts/migrate.ts:3` reads `process.env.DATABASE_URL`.** It's a script, and `loadConfig`
  would demand `TOTP_ENC_KEY`, which migrations don't need.
- **`apps/api/src/money.ts` vs `apps/mobile/src/format.ts`, `api/types.ts` DTO mirrors,
  `QUICK_COUNT` vs `QUICK_CATEGORY_COUNT`.** These are intentional cross-runtime mirrors (§1).
- **`money()` divides `cents / 100`, and `convertPreview` uses float maths** (`format.ts:11,62-65`).
  Display and preview only; sums are integer cents and the server re-prices.
- **`confirmDelete` and `client.ts` branch on `Platform.OS`.** These are the edges §5 names.
- **`budgetCents={null}`.** It's the seam §1 calls for.
- **`undo.ts` module-level singleton.** It's a documented one-shot handoff between Expense and
  Category.
- **`ScrollView` + `map` instead of `FlatList`.** That's ~15 categories, or one category's month,
  and it's keyed.
- **The `useMonth` `exhaustive-deps` suppression.** It's the reload-trigger idiom, with a reason comment.
- **The app has no test runner.** It's a known, documented gap (§6), not a defect. Once briefs
  003–006 have moved pure logic into `format.ts` and `data/`, adding Vitest for those modules is
  a small follow-up brief worth considering.
