# Refactor roadmap, November 2026

A read-only scan of `apps/api/src`, `apps/mcp/src` and `apps/mobile/src` on 2026-11-27 (`main` at 62ca655b), after the
design-system roll-out (103–106) and brief 110. It replaces the older roadmap's D, E, F and H rows in `BACKLOG.md`.

Every row is one behaviour-preserving PR, run through `/kopiyka-hos-refactoring` from `origin/main` after the row
before it has merged. Each PR writes its own brief (`docs/features/<NNN>-<slug>/brief.md`, `Type: chore`) from its row,
and is a **patch** bump (conventions §8b: behaviour-preserving refactor). Rows that share files must run in order; the
order below already respects that.

Rules for every row (`kopiyka-refactoring`):

- Nothing observable changes: API responses, error codes, SQL effects, what the app shows, and the demo build's module
  list (`apps/mobile/demo-modules.txt`) unless the row says so.
- Existing tests pass unmodified. Pure logic that moves gets characterization tests first.
- Screen changes have no automated test (the app has no render tests): check them on web at 390×844 in light and dark,
  and compare layout snapshots where the row says so (the script is in `docs/design/layout-snapshots.md`).
- One kind of change per commit: rename, extract, move, or reuse.
